## Risks
- **Swagger drift**: springdoc may emit `tags` on `Task` as not required, or name the request schema
  `TaskTagsRequest` instead of `TaskTags`; either breaks the frontend's generated client. T011 fixes
  it with `@Schema(requiredMode = REQUIRED)` / `@Schema(name = "TaskTags")`, only after checking the
  annotation attribute exists in the springdoc 3.1.1 / swagger-annotations version on the classpath.
- **Eager collection in other suites**: dashboard and plan tests load tasks; an EAGER `tags` collection
  could change query counts or fail tests that assert exact SQL/row counts. If so, T012 fixes the
  cause in the test setup or code, without weakening the assertions; if the fix would change
  behaviour, the session stops with a question.
- **Coverage gate**: phase-01 added domain code (`Task.addTags` / `removeTag`, `TaskService`); the
  phase-01 tests should cover it, but if coverage drops below 0.80 the missing lines get tests.
- **Frontend dependency**: any change to `loops/backend-dev/outputs/openapi.json` here changes the
  input of the frontend layer's client generation (already implemented for US1). Annotation-only
  fixes that make the swagger *match the contract* are what the frontend planned against, so they
  should not break it; the testing loop's checks will show if they do.
